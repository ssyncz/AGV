## 第1章 绪论

### 1.1 研究背景与问题定义

AGV 调度模块需要回答三个相互关联的问题：

1. 从起点到终点应该走哪条路；
2. 单台 AGV 连续执行多个任务时，任务应按什么顺序完成；
3. 多台 AGV 同时工作时，如何把任务分配到不同车辆，并确定每台车内部的任务顺序。

三个问题构成自底向上的依赖关系：路径规划提供任意两点之间的距离和时间，单 AGV 调度在距离基础上优化任务顺序，多 AGV 调度进一步联合优化“任务分配 + 车辆内顺序 + 避碰等待”。

### 1.2 系统约束

系统在算法中考虑了以下实际约束：

| 约束 | 含义 | 处理方式 |
| --- | --- | --- |
| 道路连通 | 起点和终点之间必须存在可行路径 | 图上无路径时返回明确错误 |
| AGV 状态 | 只有空闲 AGV 可以接受任务 | 非空闲车辆不参与分配 |
| 电量 | 剩余电量不能低于 15% | 低于阈值直接判定不可行 |
| 载重 | 任务货物重量不能超过车辆额定载重 | 超载车辆不参与分配 |
| 装卸时间 | 取货和放货需要时间 | 取货 6 s、放货 6 s |
| 安全间隔 | 两车不能同时占用同一节点 | 节点预约区间之间保留 2 s 安全间隔 |
| 任务优先级 | 高优先级任务应尽量早完成 | 计入优先级加权完成时间 |
| 多目标权衡 | 完工时间、车辆数、距离、等待时间需要折中 | 加权和综合目标函数 |

### 1.3 评价目标与指标

评价指标包括路径距离与目标值、makespan、总距离、总等待时间、使用 AGV 数量、求解时间、相对最优差距、可行率和可复现性。

| 指标 | 作用 |
| --- | --- |
| 路径距离/目标值 | 衡量解的质量 |
| makespan | 衡量整批任务的最晚完成时间 |
| 总距离 | 衡量车辆总行驶成本 |
| 总等待时间 | 衡量多车冲突带来的额外时间 |
| 使用 AGV 数量 | 衡量设备占用成本 |
| 求解时间 | 衡量算法是否满足交互式调度需求 |
| 相对最优差距 | 衡量启发式算法离精确解有多远 |
| 可行率 | 衡量算法是否满足电量、载重、连通性等约束 |
| 可复现性 | 固定随机种子后结果是否稳定 |

评价遵循以下原则：

1. 先设置硬约束，再比较目标值；
2. 同时记录相对改进率和绝对指标；
3. 不把默认实现等同于最优实现；
4. 不用单个算例代表所有规模；
5. 对小规模精确算法和大规模启发式算法分开评价。

## 第2章 系统建模

### 2.1 地图建模

仓库平面被抽象为带权无向图：

$$
G=(V,E,W)
$$

其中：

- \(V\) 是地图节点集合；
- \(E\) 是道路集合；
- \(W\) 是道路距离权重。

演示地图采用 12×8 网格，去掉 10 个矩形障碍区域后得到 76 个可通行节点和 103 条双向道路，单格边长为 4 m。系统使用邻接表存储：

```text
graph = {
    node_id: [(neighbor_id, distance, speed_limit), ...]
}
```

选择邻接表而不是邻接矩阵，是因为当前地图是稀疏图：76 个节点只有 103 条边。若使用邻接矩阵，需要存储 \(76 \times 76\) 个元素，其中绝大多数为空，空间利用率低。

### 2.2 一次任务的路径构成

一个运输任务包含取货点和放货点。完整路线由两段路径拼接：

1. AGV 当前位置 → 取货点；
2. 取货点 → 放货点。

第一段为空驶，第二段为载货行驶。系统在拼接时去掉两段路径的重复接点，并生成：

- 节点序列；
- 分段距离；
- 预计到达时间；
- 装卸时间；
- 避碰等待；
- 电量变化。

```mermaid
flowchart LR
    A[AGV 当前位置] -->|Dijkstra| B[取货点]
    B -->|装载 6 s| C[载货行驶]
    C -->|Dijkstra| D[放货点]
    D -->|卸载 6 s| E[任务完成]
```

### 2.3 单 AGV 目标函数

单 AGV 多任务顺序优化的主要目标是使整批任务总行驶距离最短。若任务顺序为：

$$
\pi=(i_1,i_2,\ldots,i_n)
$$

则总距离为：

$$
D(\pi)=d(s,p_{i_1})+d(p_{i_1},q_{i_1})
+\sum_{k=2}^{n}\left[d(q_{i_{k-1}},p_{i_k})+d(p_{i_k},q_{i_k})\right]
$$

其中：

- \(s\) 是 AGV 初始位置；
- \(p_i\) 是任务 \(i\) 的取货点；
- \(q_i\) 是任务 \(i\) 的放货点；
- \(d(a,b)\) 是两点之间的最短路径距离。

### 2.4 多 AGV 综合目标函数

多 AGV 调度需要同时优化多个目标。系统采用加权和：

$$
J=C_{\max}+w_a N_{\mathrm{AGV}}+w_w W+w_d D+w_p\sum_i \mathrm{priority}_i C_i
$$

默认参数为：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| \(w_a\) | 30.0 | 每增加一台 AGV 的惩罚 |
| \(w_w\) | 0.20 | 每等待 1 s 的惩罚 |
| \(w_d\) | 0.005 | 每行驶 1 m 的惩罚 |
| \(w_p\) | 0.02 | 优先级加权完成时间系数 |

其中：

- \(C_{\max}\) 是 makespan；
- \(N_{\mathrm{AGV}}\) 是实际使用的 AGV 数量；
- \(W\) 是总避碰等待时间；
- \(D\) 是总行驶距离；
- \(C_i\) 是任务 \(i\) 的完成时刻。

加权和法便于解释，但权重需要人工设定。实验同时报告 makespan、距离、等待时间和用车数量，以观察各指标之间的取舍。

## 第3章 路径规划算法评价

### 3.1 候选算法

路径规划部分比较了三种算法：

| 算法 | 基本思想 | 是否考虑边权 | 是否保证最短距离 |
| --- | --- | --- | --- |
| BFS | 按边数逐层扩展 | 否 | 仅在边权相等时成立 |
| Dijkstra | 每次扩展当前距离最小的节点 | 是 | 是 |
| A* | Dijkstra + 启发式函数 | 是 | 启发函数可采纳时是 |

### 3.2 Dijkstra 算法

Dijkstra 使用优先队列维护待扩展节点。设 \(dist[v]\) 为从起点到节点 \(v\) 的当前最短距离，则松弛操作为：

$$
dist[v]=\min\left(dist[v],dist[u]+w(u,v)\right)
$$

其中 \(u\) 是当前弹出的最小距离节点，\(w(u,v)\) 是边权。

堆优化后的时间复杂度为：

$$
O((V+E)\log V)
$$

当前地图有 76 个节点和 103 条边，因此单次路径规划的图规模很小。

### 3.3 A* 算法

A* 在 Dijkstra 的基础上加入启发函数 \(h(v)\)：

$$
f(v)=g(v)+h(v)
$$

其中：

- \(g(v)\) 是从起点到 \(v\) 的已知距离；
- \(h(v)\) 是 \(v\) 到终点的估计距离。

本实验使用曼哈顿距离乘单格边长作为启发函数。由于当前地图只允许上下左右移动，且所有边长均为 4 m，因此该启发函数是可采纳的。

### 3.4 实验设置

实验使用项目真实演示地图：

- 网格：12×8；
- 节点：76；
- 道路：103；
- 障碍矩形：10；
- 单格距离：4 m。

比较内容包括：

1. 示例路径：`CHARGE → HOME1`；
2. 全部 76×76=5776 个起终点组合；
3. Dijkstra 与 A* 的路径距离是否一致；
4. 平均扩展节点数和单次运行时间；
5. 路径缓存前后的查询耗时；
6. BFS 在加权图上的反例。

### 3.5 实验结果

#### 3.5.1 示例路径

| 项目 | 结果 |
| --- | ---: |
| 起点 → 终点 | `CHARGE → HOME1` |
| 路径节点数 | 19 |
| 路径距离 | 72.0 m |
| AGV 速度 | 1.2 m/s |
| 预计行驶时间 | 60.0 s |

结果与项目已有运行记录一致：`CHARGE → HOME1` 共 19 个节点、72 m，约 60 s。

#### 3.5.2 Dijkstra 与 A* 全源对比

| 指标 | Dijkstra | A* |
| --- | ---: | ---: |
| 查询数量 | 5776 | 5776 |
| 距离一致数量 | 5776 | 5776 |
| 平均单次时间 | 0.020434 ms | 0.012273 ms |
| 平均扩展节点数 | 38.50 | 约 14.64 |

A* 在当前地图上减少了约 62% 的节点扩展，单次查询速度约为 Dijkstra 的 1.66 倍。但两者的绝对耗时都只有几十微秒，相对于数据库访问、网络请求和调度评估，差异可以忽略。

#### 3.5.3 路径缓存效果

在 5000 次随机起终点查询中：

| 模式 | 平均单次耗时 |
| --- | ---: |
| 未命中缓存的 Dijkstra | 约 20.87 μs |
| 命中缓存 | 约 0.104 μs |

缓存带来约 201.58 倍加速。这个结果对多 AGV 调度尤其重要，因为 VND 在搜索过程中会对同一批起终点反复计算距离。

#### 3.5.4 BFS 反例

构造一个加权图：

- `0 → 3` 直接边权为 100；
- `0 → 1 → 2 → 3` 的边权分别为 1、1、1。

实验结果：

| 算法 | 路径 | 总距离 |
| --- | --- | ---: |
| BFS | `0 → 3` | 100 |
| Dijkstra | `0 → 1 → 2 → 3` | 3 |

BFS 只按边数扩展，因此在该反例中选择了距离更长的 100 m 路径；Dijkstra 找到 3 m 路径。边权不完全相等时，BFS 不能保证距离最优。

当前演示地图的所有道路长度均为 4 m，两种算法在这张图上得到相同距离。该结果只适用于等权图。

### 3.6 算法选择与理由

综合考虑后，路径规划采用 Dijkstra + 路径缓存，原因如下：

1. 当前道路距离均为正权，满足 Dijkstra 的适用条件；
2. Dijkstra 在加权图上保证最短距离，比 BFS 更通用；
3. A* 虽然在本实验中最快，但绝对加速只有约 0.008 ms/次；
4. A* 需要为每个终点设计启发函数，当前地图规模下工程收益不足；
5. Dijkstra 实现简单、行为稳定，便于与缓存、时间窗和电量约束集成；
6. 路径缓存使重复查询降到约 0.1 μs，是实际调度中更重要的性能来源。

A* 在当前地图上更快，但每次仅节省约 0.008 ms。考虑实现复杂度和地图规模，暂不替换主算法。

在当前 76 节点的小规模地图上，Dijkstra 的绝对耗时已经足够低；A* 的额外复杂度不能带来与工程成本相匹配的收益。

### 3.7 局限与改进

当前路径规划存在以下局限：

1. 只考虑静态图，没有处理动态障碍和临时封路；
2. 缓存需要在道路、节点或障碍变化时失效；
3. 当前地图边权以距离为主，未把拥堵、道路容量和能耗纳入路径代价；
4. 只返回一条最优路径，没有提供备选路径；
5. 多车时间窗只约束节点占用，没有显式建模边冲突和死锁。

后续可扩展方向：

- 加入动态障碍重规划；
- 使用 A* 或 D* Lite 处理大图；
- 将拥堵和等待时间加入边权；
- 引入边时间窗和预约表；
- 使用 K 短路生成备选路径；
- 在真实地图规模增大后重新比较 Dijkstra 与 A*。

## 第4章 单台 AGV 多任务顺序优化

### 4.1 问题规模

若有 \(n\) 个任务，则全部任务顺序有 \(n!\) 种：

| 任务数 | 排列数 |
| ---: | ---: |
| 4 | 24 |
| 6 | 720 |
| 8 | 40320 |
| 10 | 3628800 |
| 14 | 87178291200 |

任务数增大后，穷举法很快不可行。

### 4.2 状态压缩动态规划

状态定义为：

$$
(mask,last)
$$

其中：

- \(mask\) 表示已经完成的任务集合；
- \(last\) 表示最后一个完成的任务。

状态值表示完成集合 `mask` 中的任务、且最后完成任务 `last` 时的最小行驶距离。

转移方程：

$$
dp[mask\cup\{k\}][k]
=\min_{last\in mask}\left(dp[mask][last]+c(last,k)\right)
$$

其中：

$$
c(last,k)=d(q_{last},p_k)+d(p_k,q_k)
$$

时间复杂度为：

$$
O(n^2 2^n)
$$

空间复杂度为：

$$
O(n 2^n)
$$

DP 的正确性来自两个性质：

1. 无后效性：当前状态只由“已完成任务集合”和“最后任务”决定；
2. 最优子结构：全局最优顺序一定由某个子问题的最优顺序扩展得到。

### 4.3 启发式算法：最近邻 + 2-opt

当任务数较大时，使用最近邻构造初始顺序：

1. 从当前位置出发；
2. 每次选择距离当前节点最近的未完成任务；
3. 将任务加入顺序，并把当前位置更新为该任务的放货点。

最近邻构造速度快，但容易陷入局部最优。随后使用 2-opt 改进：

1. 在任务序列中选取一段连续区间；
2. 反转该区间；
3. 若总距离下降则保留；
4. 重复直到没有改进。

2-opt 时间复杂度约为 \(O(n^2)\) 每轮，不能保证全局最优，但通常能显著修正交叉路线。

### 4.4 实验设置

实验使用项目真实地图和 `TASK_TEMPLATES` 任务模板：

- AGV：`AGV-03`；
- 起点：`S3`；
- 任务数：4、6、8、10、12、14；
- 每个任务数随机抽取 5 组任务集合；
- 精确解：状态压缩 DP；
- 对照算法：输入顺序基线、最近邻 + 2-opt；
- 小规模额外对照：暴力枚举。

说明：

- 应用代码在 \(n\le 10\) 时使用 DP；
- \(n=12,14\) 的精确 DP 仅用于报告中的离线对照，应用主流程仍使用 NN+2-opt；
- 距离使用项目地图上的 Dijkstra 最短路径；
- 每组结果取 5 个随机任务集合的平均值。

### 4.6 结果分析

#### 4.6.1 输入顺序基线明显较差

输入顺序相对精确 DP 的距离差距为：

- \(n=4\)：35.21%；
- \(n=6\)：38.83%；
- \(n=8\)：51.74%；
- \(n=10\)：52.38%；
- \(n=12\)：49.66%；
- \(n=14\)：59.23%。

任务到达顺序与总距离存在明显差距，因此顺序优化有实际作用。

#### 4.6.2 DP 的精确性

在 \(n\le 8\) 时，DP 与暴力枚举得到相同的最短距离；在全部测试规模中，DP 距离均不高于 NN+2-opt。

DP 在 \(n=8\) 时耗时约 0.78 ms，而暴力枚举约 13.39 ms，说明状态压缩 DP 显著减少了重复子问题。

#### 4.6.3 启发式质量

NN+2-opt 相对精确 DP 的平均差距在 2.93% 到 10.35% 之间：

- 小规模下差距较小，且求解时间低；
- 大规模下无法保证最优，但可以在亚毫秒级得到可接受解；
- 差距并非随任务数单调增大，说明结果受任务空间分布影响。

#### 4.6.4 关于 10 个任务的阈值

实验显示：

- \(n=10\) 时 DP 平均约 5.61 ms；
- \(n=12\) 时约 35.14 ms；
- \(n=14\) 时约 190.02 ms。

在测试机器上，\(n=10\) 的 DP 平均约 5.61 ms，\(n=12\) 约 35.14 ms，\(n=14\) 约 190.02 ms。10 个任务的阈值偏保守；继续增大任务数会快速增加时间和内存。

因此，10 是当前实现为控制最坏响应时间设置的保守阈值，可按部署环境调整。

10 是当前系统为了控制最坏情况响应时间和内存占用而设置的保守阈值；该阈值应当可配置，并应根据部署机器性能和任务分布重新标定。

### 4.7 算法选择与理由

最终采用分规模策略：

| 任务数 | 算法 | 理由 |
| --- | --- | --- |
| \(n\le 10\) | 状态压缩 DP | 可得到精确最优解，当前规模下响应时间可接受 |
| \(n>10\) | 最近邻 + 2-opt | 避免指数级状态爆炸，能在毫秒级得到近似解 |

单 AGV 模块的实际运行记录中，4 个任务的 makespan 从 350.3 s 降到 306.6 s，综合目标改进 15.33%。该结果用于说明算法在真实任务链路上的效果；本节的随机算例则用于说明 DP 与启发式的相对质量。

### 4.8 局限

1. DP 的目标是总距离最短，不直接优化 makespan；
2. 装卸时间、避碰等待和多车预约在完整调度评估阶段才计入；
3. NN+2-opt 不能保证全局最优；
4. 任务数增加时，DP 的时间和内存增长很快；
5. 电池和载重约束会影响车辆选择，但不进入单 AGV 任务顺序距离本身；
6. 当前只有 5 组随机任务集合，仍需扩充算例和交叉验证。

## 第5章 多台 AGV 联合调度

### 5.1 问题性质

多 AGV 调度需要同时决定：

1. 每个任务分配给哪台 AGV；
2. 每台 AGV 内部按什么顺序执行任务；
3. 多车路径发生时间冲突时如何等待。

该问题包含车辆路径问题（VRP）的分派与排序结构，属于 NP 难问题。任务数较大时，精确求解的计算量迅速增加，系统采用构造初始解和局部搜索改进的工程方案。

### 5.2 对比算法

| 算法 | 类型 | 作用 |
| --- | --- | --- |
| 基线：优先级 + 最早完成 | 贪心 | 提供不优化时的对照标准 |
| 最优插入 | 构造式启发式 | 生成较高质量的初始解 |
| 最优插入 + VND | 局部搜索 | 在初始解基础上继续优化 |

#### 5.2.1 基线算法

基线算法按任务优先级和提交时间排序，对每个任务尝试所有可用 AGV，把它追加到车辆任务列表末尾，选择完成时间最早的车辆。

优点是速度快、行为稳定；缺点是只看当前任务，不考虑后续任务，容易把负载集中到同一辆车。

#### 5.2.2 最优插入

最优插入按任务顺序逐个处理。对每个任务：

1. 遍历所有可用 AGV；
2. 遍历该车任务列表的所有插入位置；
3. 完整评估候选方案的目标值；
4. 保留目标值最小的方案。

相比“追加到末尾”，最优插入允许把新任务插入已有任务之间，即允许“顺路捎带”。

#### 5.2.3 变邻域下降

VND 从插入解出发，依次尝试四类邻域：

| 邻域 | 动作 | 作用 |
| --- | --- | --- |
| relocate | 将任务移动到本车其他位置或其他车辆 | 调整分配和顺序 |
| swap | 交换两个任务 | 快速修正顺序错误 |
| or-opt | 整体移动 2～3 个连续任务 | 保持任务块结构 |
| 2-opt | 反转本车一段任务序列 | 消除交叉路线 |

搜索策略为首次改进接受：某邻域找到改进解后立即接受，并回到第一个邻域重新搜索；四个邻域都无改进时停止。

当前实现参数：

- 最大轮数：50；
- 每轮最多评估邻居：120；
- VND 时间预算：3 s；
- 固定随机种子：20260928；
- 邻居过多时使用固定种子采样，保证可复现。

### 5.3 时间窗避碰

多车同时运行时，同一节点可能被多台车在同一时段占用。系统为每个节点维护预约列表：

```text
reservations[node_id] = [
    {start, end, agv_id, task_id},
    ...
]
```

车辆到达节点时，检查该节点的已有预约。如果时间区间重叠，则把到达时间顺延到冲突区间结束后，并额外保留 2 s 安全间隔。

等待时间计入目标函数，算法会在调整分配和增加等待之间权衡。

### 5.4 实验设置

实验分为两部分。

#### 5.4.1 当前仓库地图

使用：

- 地图：76 节点 / 103 条道路；
- AGV：4 台；
- 任务：前 6 个演示任务；
- 综合目标：默认权重；
- 算法：基线、最优插入、最优插入 + VND。

#### 5.4.2 合成规模实验

使用 Solomon 风格的聚类平面算例：

- 区域：100×100；
- depot：中心点；
- 客户：10、20、30 个；
- AGV：2、3、4 台；
- 随机种子：42、43、44、45、46；
- 共 3 种规模 × 5 个种子 = 15 个算例。

本实验使用 Solomon 风格的坐标、需求和车辆规模，未引入客户时间窗，因此结果不等同于完整 CVRPTW 基准。

### 5.5 当前地图实验结果

| 算法 | 综合目标 | makespan/s | 总距离/m | 等待/s | 用车 | 求解时间/s | 综合目标改进 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 基线：优先级 + 最早完成 | 295.14 | 149.64 | 276.0 | 12.08 | 4 | 0.011 | — |
| 最优插入 | 276.94 | 131.71 | 268.0 | 12.08 | 4 | 0.017 | 6.17% |
| 最优插入 + VND | 276.15 | 131.71 | 284.0 | 4.00 | 4 | 1.239 | 6.44% |

关键结论：

1. 基线 makespan 为 149.64 s，插入和 VND 均为 131.71 s，makespan 改进 11.98%；
2. 综合目标从 295.14 降到 276.15，改进 6.44%；
3. 几乎全部综合目标收益来自最优插入，VND 相对插入解只再改进约 0.29%；
4. VND 将等待时间从 12.08 s 降到 4.00 s，但总距离从 268 m 增加到 284 m；
5. 当前场景下 makespan 没有再下降，说明 VND 的改进主要体现在等待与距离之间的目标权衡；
6. 4399 次邻域评估后得到最终解，求解时间约 1.24 s。

这组结果说明：

不能把 6.44% 全部归因于 VND。更准确的表述是：最优插入贡献了大部分改进，VND 在插入解基础上进一步调整等待和距离的权衡。

### 5.7 VND 邻域消融

在 20 客户 / 3 AGV、随机种子 42 的算例上，从同一个最优插入解出发，分别限制运行 0.8 s：

| 邻域 | 初始目标 | 最终目标 | 改进 | 迭代次数 |
| --- | ---: | ---: | ---: | ---: |
| relocate | 795.60 | 791.13 | 0.56% | 296 |
| swap | 795.60 | 773.68 | 2.75% | 386 |
| or-opt | 795.60 | 792.12 | 0.44% | 266 |
| 2-opt | 795.60 | 791.13 | 0.56% | 398 |
| 四邻域组合 | 795.60 | 782.40 | 1.66% | 408 |

需要注意以下三点：

1. 在这个算例和 0.8 s 短预算下，`swap` 单项表现最好；
2. 四邻域组合没有单调优于单项，说明邻域组合的有效性依赖实例结构、时间和随机采样；
3. 四邻域组合没有单调优于单项，结果与实例结构、时间预算和随机采样有关。主实现保留四邻域，用于提高跨实例适应性。

### 5.8 多 AGV 算法选择

| 算法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 基线贪心 | 极快、易解释 | 容易负载集中，目标值较差 | 作为对照，不作为最终方案 |
| 最优插入 | 质量较高，成本低 | 仍是贪心构造，可能陷局部最优 | 作为初始解 |
| 插入 + VND | 可继续改善目标，支持多种邻域 | 时间更长，不能保证全局最优 | 作为最终方案 |

多 AGV 调度采用“最优插入 + VND”的组合，原因如下：

1. 当前问题规模下，精确求解多车分配与排序不现实；
2. 纯基线贪心质量不足；
3. 最优插入能以较低成本得到较强的初始解；
4. VND 可以在初始解基础上继续权衡等待、距离和车辆分配；
5. 固定种子和邻居采样使结果可复现；
6. 时间预算可以控制大规模算例的响应时间。

### 5.9 局限

1. VND 是局部搜索，不能保证全局最优；
2. 综合目标权重由人工设定，用户偏好会影响最终方案；
3. 时间窗只约束节点，没有显式建模边冲突、相向冲突和循环等待死锁；
4. 3 s 时间预算只约束 VND 搜索，不包含初始解和完整评估时间，因此总耗时可超过 3 s；
5. 合成算例没有客户时间窗，不能替代完整 Solomon CVRPTW；
6. 结果对机器性能和随机采样敏感，需要报告运行环境；
7. 当前没有与 OR-Tools、遗传算法等求解器进行同口径比较。

## 第7章 综合讨论

### 7.1 算法评价汇总

| 算法 | 实验作用 | 关键结果 | 结论 |
| --- | --- | --- | --- |
| BFS | 路径规划反例 | 加权图中选 100 m 路径，Dijkstra 选 3 m | 不适用于非等权图 |
| Dijkstra | 主路径算法 | 平均 0.020 ms/次 | 采用 |
| A* | Dijkstra 替代方案 | 平均 0.012 ms/次，距离一致 | 未采用，收益不足以抵消复杂度 |
| 暴力枚举 | 小规模正确性对照 | \(n=8\) 时 13.39 ms | 仅用于验证 |
| 精确 DP | 小规模精确解 | \(n=10\) 时 5.61 ms | 采用 \(n\le 10\) |
| NN+2-opt | 大规模近似解 | 相对最优差距 2.93%～10.35% | 采用 \(n>10\) |
| 基线贪心 | 多 AGV 对照 | 当前地图 makespan 149.64 s | 作为基线 |
| 最优插入 | 初始解 | 综合目标改进 6.17% | 采用 |
| 插入 + VND | 最终方案 | 综合目标改进 6.44%，等待 12.08 s → 4.00 s | 采用 |

### 7.2 主要结论

1. Dijkstra 在当前小规模静态地图上足够快，路径缓存比更换算法带来更大的工程收益；
2. A* 虽然减少扩展节点，但绝对时间差异过小，暂不作为主算法；
3. 任务顺序优化对小规模场景有显著价值，DP 能保证最优；
4. 10 个任务的 DP 阈值是保守工程折中，不是理论极限；
5. NN+2-opt 在大规模下速度快，但存在约 3%～10% 的最优差距；
6. 多 AGV 调度的主要收益来自最优插入，VND 提供额外改进但增量有限；
7. 当前场景中 VND 通过增加 16 m 距离换取 8.08 s 等待时间下降，体现了多目标权衡；
8. 综合目标改进率与 makespan 改进率不能混用；
9. 多车时间窗目前只处理节点冲突，不能宣称已经完全避免碰撞和死锁。

### 7.3 选型反思

本模块的三个算法都不是“越复杂越好”：

- BFS 最简单，但不支持加权图；
- A* 比 Dijkstra 更快，但当前规模下收益很小；
- 暴力枚举最直接，但规模稍大就不可用；
- DP 能给出精确解，但只适合小规模；
- 启发式算法牺牲最优性换取可扩展性；
- VND 能继续改进，但不能保证全局最优。

算法选择主要受问题规模、约束条件和工程成本影响。

## 结　论

本文完成 AGV 智能调度系统中路径规划、单台 AGV 任务排序和多台 AGV 联合调度的算法实现与实验评价。路径规划采用 Dijkstra 并加入查询缓存，在当前 76 节点地图上能够稳定得到最短路径。单台 AGV 调度在 10 个任务以内使用状态压缩 DP，更大规模使用最近邻与 2-opt，兼顾最优性和响应时间。多台 AGV 调度采用最优插入构造初始解，再用变邻域下降调整任务分配和车内顺序。

实验结果表明，当前 6 任务 4 AGV 场景的 makespan 从 149.64 s 降到 131.71 s，综合目标改进 6.44%。其中最优插入贡献 6.17%，VND 在插入解上继续改进约 0.29%。这些结果说明算法能够改善调度方案，也暴露出多目标权重、节点级避碰和启发式最优性方面的限制。

### 研究局限与后续工作

1. 将 DP 阈值做成可配置参数，并用更多机器和任务分布重新标定；
2. 增加更多随机种子和更大规模算例，报告置信区间；
3. 增加 VND 关闭/开启、单邻域/多邻域的完整对照；
4. 加入边时间窗、死锁检测和回退机制；
5. 将客户时间窗真正纳入 Solomon CVRPTW 实验；
6. 与 OR-Tools、遗传算法等进行同口径比较；
7. 增加动态障碍和临时封路重规划；
8. 增加真实 AGV 遥测数据下的在线调度实验；
9. 将结果接入前端甘特图和路线回放，形成完整演示链路。
