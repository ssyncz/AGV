# 企业级业务闭环集成说明

本次改造把原来的“多个并列算法页面”收敛为一条制造运营业务链：

```text
订单预测 → 生产计划 → 生产工单 → 运输任务 → AGV 调度执行
                                      ├→ 视觉质检 → 放行 / 返工 / 阻塞
                                      └→ 设备诊断 → 告警 / 阻塞 / 恢复
```

## 1. 统一业务核心

新增 `Operations` 应用，提供跨模块共享的主数据和追溯能力：

- `Site`：工厂、车间或仓库；
- `Product`：产品主数据；
- `Equipment`：设备主数据；
- `WorkOrder`：生产工单，统一业务主线；
- `OperationStep`：工单下的工序级执行单元；
- `WorkCalendar`：站点班次日历与资源可用窗口；
- `Alert`：设备、质量、交期等统一告警；
- `OperationEvent`：跨模块业务事件；
- `AuditLog`：关键状态变更审计；
- `ExecutionEvent`：外部 RCS/MES 执行事件的幂等接收记录。

其他模块通过外键接入：

- `TransportTask.work_order`；
- `TransportTask.operation_step`；
- `ProductionPlan.work_order`；
- `VisionRecord.work_order` 与 `quality_result`；
- `EquipmentDiagnosisRecord.equipment` 与 `work_order`。

## 2. 状态机

工单下默认生成四类工序：

```text
010 物料配送 → 020 生产加工 → 030 质量检验（质量门禁） → 040 完工入库
```

运输任务只属于“物料配送”工序，生产加工、质量检验和完工入库由工序状态推进。
工序必须按顺序执行，前序工序未完成时不能开始后续工序。

工单状态：

```text
draft → released → in_progress → quality_check → completed
                         ↘ blocked → quality_check / in_progress
                         ↘ cancelled
```

- 工单必须下达后才能开始；
- 仍有未完成运输任务时不能提交质检或完成；
- 质检不合格会自动阻塞工单；
- 设备故障或磨损会自动阻塞关联工单；
- 质检复检通过后，工单可以恢复到待质检状态；
- 所有状态变化写入 `OperationEvent` 和 `AuditLog`。

## 3. 闭环联动

### 预测到工单

调用 `POST /api/v1/production-plans/generate/` 后：

1. 生成 `ProductionPlan`；
2. 自动生成执行工单；
3. 自动生成带释放时间与交期的运输任务；
4. 计划、工单、运输任务三者互相可追溯。

生产计划排程支持**按可行批量执行**：当空闲车辆数量、载重或电量不足以一次完成整批任务时，
系统会从较小批量开始寻找可行方案，只分配当前能执行的任务；剩余任务保持 `pending`，
可在车辆完成当前批次、释放或充电后继续排程。响应中的 `scheduled_task_count` 和
`remaining_task_count` 用于展示本次分配数量与剩余数量。

### 质检到工单

视觉检测接口支持可选参数 `work_order_id`：

- 裂纹任务默认根据检测结果生成 `pass` 或 `fail`；
- 缺陷分类任务关联工单时默认按 `fail` 处理；
- 也可以显式传入 `quality_result=pass|fail|not_assessed`；
- 不合格会生成严重告警并阻塞工单。

### 设备到工单

设备诊断接口支持可选参数 `work_order_id`：

- `normal`：设备恢复正常并解决未关闭的设备告警；
- `worn`：生成警告并阻塞关联工单；
- `fault`：生成严重告警并阻塞关联工单。

### 外部执行事件

`POST /api/v1/operations/execution-events/ingest/` 支持：

```text
transport_task.started
transport_task.completed
operation_step.started
operation_step.completed
```

请求必须提供唯一的 `external_id`。相同 `external_id` 重复提交时返回已有事件，
不会重复推进工单或任务状态。

## 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/operations/command-center/` | 生产总览聚合 KPI、告警、工单与事件 |
| GET/POST | `/api/v1/operations/work-orders/` | 工单列表与创建 |
| POST | `/api/v1/operations/work-orders/{id}/release/` | 下达工单 |
| POST | `/api/v1/operations/work-orders/{id}/start/` | 开始执行 |
| POST | `/api/v1/operations/work-orders/{id}/quality-check/` | 提交质检 |
| POST | `/api/v1/operations/work-orders/{id}/complete/` | 完成工单 |
| POST | `/api/v1/operations/work-orders/{id}/block/` | 阻塞工单 |
| POST | `/api/v1/operations/work-orders/{id}/resume/` | 恢复工单 |
| POST | `/api/v1/operations/work-orders/{id}/transport-tasks/` | 工单新增运输任务 |
| GET | `/api/v1/operations/work-orders/{id}/timeline/` | 工单全链路时间线 |
| GET/POST | `/api/v1/operations/operation-steps/` | 工单工序查询 |
| POST | `/api/v1/operations/operation-steps/{id}/start/` | 开始工序 |
| POST | `/api/v1/operations/operation-steps/{id}/complete/` | 完成工序 |
| GET/POST | `/api/v1/operations/work-calendars/` | 班次日历管理 |
| POST | `/api/v1/operations/execution-events/ingest/` | RCS/MES 外部执行事件接入 |
| GET | `/api/v1/operations/alerts/` | 告警中心 |
| GET | `/api/v1/operations/master-data/` | 站点、产品、设备主数据 |

旧 `/api/` 路径继续保留，`/api/v1/` 用于版本化接入。

## 5. 前端信息架构

前端已接入 Vue Router，按业务域组织：

- 运营：生产总览、生产工单、告警中心；
- 生产执行：调度中心、运输任务、地图监控、生产计划；
- 资源与质量：AGV 管理、设备监测、视觉质检；
- 计划与系统：订单预测、主数据管理。

工单支持 URL 深链接，例如：

```text
http://127.0.0.1:5173/#/work-orders?work_order=12
```

## 6. 启动与迁移

```powershell
python manage.py migrate
python manage.py runserver
cd frontend
npm install
npm run dev
```

本地无 MySQL 时可以用 SQLite 验证：

```powershell
$env:DB_ENGINE = "sqlite"
python manage.py migrate
```

## 7. 权限与环境

默认保持匿名演示模式。设置以下环境变量后，DRF 将要求登录：

```text
DJANGO_API_AUTH_REQUIRED=True
```

每个请求都会生成或透传 `X-Request-ID`，用于日志、审计和事件追踪。
